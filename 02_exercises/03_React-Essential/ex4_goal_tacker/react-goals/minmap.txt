--------------------------------------------
react-goals/
├── index.html          ← real DOM entry point
├── src/
│   ├── main.jsx        ← React bootloader
│   ├── App.jsx         ← Root component (brain)
│   ├── components/
│   │   └── GoalItem.jsx ← Child component
│   └── assets/         ← images, fonts, etc.

----------------------------------------------
Why this structure exists
main.jsx → connects React to the browser
App.jsx → owns state & logic
components/ → reusable UI pieces
index.html → just a shell
React lives entirely inside one DOM node.

3. Boot Process (What Runs First)
Step-by-step reality
Browser loads index.html
<div id="root"></div> exists
main.jsx runs:
Creates React root
Renders <App />
React calls App() function
JSX → Virtual DOM
Virtual DOM → Real DOM
Nothing magical. Just functions.
---------------------------------------------
4. App Component = Control Center
Responsibilities of <App />

<App />
 ├── Holds state (goals, enteredGoal)
 ├── Handles events (addGoal)
 ├── Passes data down (props)
 └── Decides what to render

This is intentional design:

State lives high

UI lives low

This prevents chaos.
------------------------------------------
5. State Mind Map (Data Flow)

State Variables

State
├── goals (array)
│    └── ["Learn React", "Build projects"]
└── enteredGoal (string)
     └── "Learn React"

-----------------------------------------
Rules of state (non-negotiable)

State changes → re-render

Never mutate state directly

Always use setter functions

UI is a function of state

React watches data, not the DOM.
-----------------------------------------
6. Event Flow (Cause → Effect)


User Click
 └── onClick
      └── addGoal()
           ├── setGoals()
           ├── setEnteredGoal('')
           └── React re-renders


Important insight

You are not updating the UI.
You are updating data.
React updates the UI because the data changed.

This is the philosophical core of React.

7. Controlled Input Mental Model
Input Field
 ├── value = enteredGoal
 └── onChange → setEnteredGoal()


Why this matters:

React owns the input

No hidden DOM state

Predictable behavior

Easier validation later

This is why React apps don’t spiral into madness.

9. Component Boundary Logic
<GoalItem />
GoalItem
 ├── Receives props
 │    └── text
 └── Renders UI

Replaceable

Components should be boringly simple.

10. Data Direction (One-Way Flow)
State (App)
   ↓
Props
   ↓
Child Components


Never:

Child modifying parent state directly

Random cross-component access

This rule alone saves thousands of bugs.
